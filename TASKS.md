# TASKS (solo, 6 hours; the app is already built, so the day is about real data, polish and pitch)

Format: - [ ] Task. FILES: ... DONE WHEN: ...

- [ ] T1 (0:00-0:15) Run the app locally and click through every page. FILES: none. DONE WHEN: search, route page, map, admin and notices all work.
- [ ] T2 (0:15-0:45) Get real data: ask the organisers or transport office for routes, stops, times; if none, invent a realistic set for your own college area. FILES: none. DONE WHEN: a list of 3 to 5 routes with stops, minutes and times is in a notes file.
- [ ] T3 (0:45-1:45) Enter the real data through /admin (or edit `seed()` in app.py and reset the DB). FILES: app.py (optional). DONE WHEN: searching real stop names returns correct routes and times.
- [ ] T4 (1:45-2:15) Deploy to a public URL, test it on your phone, including /driver GPS. FILES: none. DONE WHEN: you can move with your phone and see the bus move on another device.
- [ ] T5 (2:15-4:00) Add ONE extra feature from SPEC "Next" (suggested: QR code per stop, or PWA install). FILES: app.py, templates/. DONE WHEN: it works on a phone and is in the demo script.
- [ ] T6 (4:00-4:45) Polish: branding (college name, colours), empty states, mobile check on a real phone. FILES: templates/. DONE WHEN: no page looks broken at phone size.
- [ ] T7 (4:45-5:30) Deck, demo script, backup video (PITCH.md has drafts). DONE WHEN: two timed rehearsals done.
- [ ] T8 (5:30-6:00) Code freeze. Final redeploy, reset demo state, warm up the site. DONE WHEN: judges' link opens in under 5 seconds.

## If behind, cut in this order
1. Extra feature (T5)  2. Public deploy (present from laptop)  3. Real data (use demo data and say so)
